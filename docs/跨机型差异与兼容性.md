# WinToolbox 跨机型差异与兼容性报告

> 目的：逐条说明「换一台机器会有哪些地方表现不同」，以及每处的**代码位置 / 不同结果 / 有没有兜底 / 是否已修**。
> 生成方式：通读 `app.py`（约 8100 行）+ `server.py`（约 7200 行）+ `web/` + 构建与测试脚本，
> 并在本机（Intel 混合架构 8P+8E / 16 逻辑核、Win11、非 100% 缩放下也验证过）实跑校准。
> 标注约定：**✅ 已处理**（本轮修了或本来就有兜底）· **⚠️ 已知差异**（设计如此，但结果确实随机器变）· **❗ 待观察**（暂不影响功能）

---

## 一、CPU / 处理器

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **是否有大小核** | `server.cpu_topology()` | Intel 混合架构能分出 `p_logicals` / `e_logicals`；**AMD 全大核、老 Intel** 所有核 `EfficiencyClass` 相同 → `p_logicals` 为空 | ✅ 已处理 |
| **按「E 核」绑定进程** | `server.set_process_affinity()` | 修前：非混合架构下 `p_logicals` 空 → 按「P」报「该组核心为空」，而按「E」拿到的是**系统兜底的全部核心** —— 用户以为限定了小核，实际一点没限；修后：先判架构，分不清就直接拒绝并说明 | ✅ 本轮修复 |
| **逻辑核 > 64** | `server.cores_to_mask()` | 双路 Xeon / Threadripper 上，≥64 的核被丢弃；掩码仍能建但只覆盖前 64 核 | ⚠️ 已知差异（已丢弃并会返回「掩码为空」错误而不是静默绑错） |
| **多处理器组（>64 核）** | `server.cpu_topology()` | 只读第一个 `GROUP_AFFINITY`，核号可能错位 | ⚠️ 已知差异（极罕见机型） |
| **CPU 温度来源** | `server.cpu_temp()` | 优先 PDH `\Thermal Zone Information(*)`（约 1ms）；**很多台式/AMD 机型没有这个计数器** → 回退 `MSAcpi_ThermalZoneTemperature`（PowerShell，约 1.4s）；再回退 `Win32_PerfFormattedData…`；都没有 → 显示「不可读」 | ✅ 三级兜底 |
| **CPU 标称频率** | `server.cpu_base_mhz()` | `CallNtPowerInformation(MaxMhz)`；个别机型返回 0 → 回退注册表 `~MHz`（Win11 上会跟着当前频率浮动） | ✅ 已兜底 |

## 二、显卡 / GPU

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **NVIDIA 独显** | `server._nvidia_smi()` | 有 `nvidia-smi.exe` 才有逐卡利用率与**温度**；装了驱动但没进 PATH 也拿不到 | ✅ 查不到就退回聚合值 |
| **AMD / Intel 独显或核显** | `server._gpu_engine_utils()` | 只有 PDH `GPU Engine` 利用率，**没有温度**（Windows 没给统一 API）；`_dx_adapters` 还要读 `HKLM\SOFTWARE\Microsoft\DirectX` | ⚠️ 已知差异（温度显示「—」） |
| **无独显 / 虚拟机** | `app.OverviewPage` GPU 卡 | 落到聚合值或显示「未检测到显卡」，温度恒为空 | ✅ 有兜底 |
| **多显卡** | `app` 概览 GPU 下拉 | 有几张卡就有几个选项；默认选独显（`is_dgpu` 判定失败时会默认选到集显） | ⚠️ 已知差异 |
| **显存大小** | `server.gpu_vram()` | 走注册表 `HardwareInformation.qwMemorySize`（避开 WMI 32 位截断）；部分驱动不写这个值 → 显存空白 | ✅ 已改为「读不到就不缓存」，装完驱动能自愈 |
| **Basic Render (WARP)** | `server._dx_adapters()` | 软件渲染适配器被过滤掉，不会当成真显卡列出 | ✅ |
| **显卡伪装** | `server.gpu_alias_apply/restore()` | 依赖 `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-…}` 下的 `DriverDesc`；**不同驱动的值名不同** → 可能找不到可改的键 | ⚠️ 已知差异（会提示失败而不是假成功） |

## 三、显示器

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **显示器型号来源** | `server.monitors()` | 读注册表 EDID（不依赖 WMI）；虚拟显示器伪造 EDID（型号写成 `HDMI2.0`、尺寸离谱）→ 用软评分排到后面 | ✅ 软评分 + 排序 |
| **两台同型号显示器** | `server.monitors()` | 修前按「型号名」去重 → **双屏同型号会少显示一台**；修后按「型号键 + 实例」去重 | ✅ 本轮修复 |
| **无 EDID 的屏** | 同上 | 拿不到 EDID 就整块跳过；结果为空时**不再缓存**（外接屏稍后插上还能再读） | ✅ 本轮修复 |

## 四、网络

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **网卡数量 / 类型** | `server.net_adapters_all()` | 走 `Get-NetAdapter`：**Win7/2008 没有这个 cmdlet** → 回退 `Get-CimInstance`；无 WiFi 的机型 `kind` 恒为「以太网」 | ✅ 有回退 |
| **速率来源** | `server._net_loop()` | 优先 PDH 网络计数器；**部分机型 PDH 计数不可用** → 回退 `Get-NetAdapterStatistics` 差值 | ✅ 已修：回退路径现在会清掉「准备中」标记，否则界面永远显示"准备中" |
| **默认选中哪张网卡** | `server._pick_primary()` | 规则是「非虚拟 + 协商速率最高」→ **WiFi 866Mbps 会压过 100M 有线网卡** | ⚠️ 已知差异（下拉可手动切换） |
| **有线/无线同时在线** | 同上 | 只显示一张为「主」，其余列在下拉里并可单独查看 | ✅ |
| **DNS 测试结果** | `server.dns_test()` | 部分公共 DNS **禁 ICMP**（如 114）→ 走 DNS 解析成功判定为「禁 ping · 可解析」 | ✅ 专门处理了 |

## 五、系统版本 / 语言 / 权限

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **Windows 10 vs 11** | `server.os_release()` | 查表覆盖 1507→25H2；**Win10 <1903 没有 `DisplayVersion`** → 用 build 兜底 | ✅ |
| **Win10 没有 Segoe UI Variable 字体** | `theme.py` 字体链 / `app.main()` | 回退 `Segoe UI` → 标题栏那个 "W" 图标字形会略有不同 | ✅ 有回退链 |
| **繁体中文系统** | `server._user_reg_root_label()` | 修前判简体用的是 `(lang & 0x3ff)==0x04`，**繁体（0x0404/0x0C04）也被判成简体** → 写出的 regedit 根节点名「计算机」在繁体系列里不存在 → 定位失效。修后简中→「计算机」、繁体→「電腦」、其它→「Computer」 | ✅ 本轮修复 |
| **DC / Server Core / 精简版** | `Get-AppxPackage` / `Get-NetAdapter` / `Get-CimInstance` | 这些 cmdlet 可能**不存在**（无 Store、无 GUI 组件）→ 对应功能返回空列表 | ⚠️ 已知差异（预装应用页现在会显示「未读到应用」而不是空表格） |
| **PowerShell 执行策略受限 / 被安全软件拦** | `server.ps()` | 返回非 0、输出是错误文本 → 多数函数落到空结果 | ✅ 已修：`sys_basic` / 主板 / 内存条 / 显存 / 显示器**不再把失败结果永久缓存**，下次调用会重试（以前这台机器整个会话都空白） |
| **非管理员运行** | 各处 | 所有 HKLM 写入会失败并如实报错；界面按钮按 `admin_mode` 置灰 | ✅ 有兜底 |
| **HKCU 被判为 HKU** | `server.reg_read()` | 修前 `reg_read` 的 hive 映射少了 `HKU` → 传 HKU 路径会被当成 HKCU 读，**静默读错另一份配置**；修后读写共用一张映射表 | ✅ 本轮修复 |
| **命令安全策略禁用某个命令行工具** | 本机实测：`sc.exe` 被安全策略直接拦死 | 起子进程的功能会失败 | ✅ 本轮已把「查服务状态」从 `sc query` 改成 `advapi32` 直读，不依赖外部命令 |

## 六、供电 / 电源

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **电源计划数量** | `server.cpu_plans()` | 笔记本通常有节能/平衡/高性能；**台式机常没有「卓越性能」**（隐藏模板，代码会先复制再启用）；精简系统可能一个都列不出 | ✅ 有兜底（下拉为空时不崩） |
| **哪一个是「当前生效」** | `server.cpu_plans()` | 修前靠 `powercfg /list` 输出里的 `*` 号判断（依赖输出格式）。修后**优先和注册表 `ActivePowerScheme` 比对**，拿不到才退回 `*` | ✅ 本轮修复 |
| **EPP 读不到** | `server._powercfg_set_hidden()` | EPP 是隐藏设置，要先 `-ATTRIB_HIDE` 才能读；修前失败也写缓存 → 该计划 EPP 永远显示空 | ✅ 本轮修复（失败记 60 秒退避后重试） |
| **无电池机型** | — | 本工具不含电池相关功能，无影响 | — |

## 七、磁盘 / 存储

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **盘符数量** | `server.disks()` | 遍历 C–Z，有几个分区显示几个；**动态磁盘 / 挂载点 / VHD** 可能列出奇怪的名字 | ⚠️ 已知差异 |
| **物理盘读写** | PDH `PhysicalDisk` | 部分 RAID / NVMe 机型拿不到逐盘计数 → 落回聚合值 | ✅ |
| **缩略图缓存文件名** | `server.clean_junk()` | 只处理 `thumbcache_256/1024.db`、`iconcache_256/1024.db` **四个硬编码名**；不同 Windows 版本命名不同会漏删 | ⚠️ 已知差异（漏删不会误删） |
| **卷上没有回收站** | `server._recycle_one()` | 残留清理默认把文件送回收站（可还原）。U 盘 / 网络盘 / 被组策略关掉回收站的卷没有 `$Recycle.Bin` → 该卷走**永久删除**，并在结果里如实写「该卷回收站不可用，已永久删除」；组策略 `NoRecycleFiles` 关掉回收站时也会走到这一步 | ✅ 有兜底（如实告知，不谎报可还原） |
| **回收站被「不移动到回收站」策略覆盖** | `server._recycle_one()` | 即使卷上有 `$Recycle.Bin`，个别机器仍可能直接永久删。所以判定**不看 API 返回码**，而是比对删除前后回收站项目数（`SHQueryRecycleBinW`）：项目数没涨就不说「可还原」 | ✅ 有兜底 |

## 八、界面 / 显示环境

| 差异点 | 代码位置 | 不同机器上的表现 | 状态 |
|---|---|---|---|
| **DPI 缩放 ≠ 100%** | `app.SplashWindow._center_on()` | 修前启动窗口把**物理像素**当逻辑坐标用 → 150%/200% 缩放下窗口被推到右下方甚至出屏；100% 缩放下恰好正确，所以只在换屏/改缩放后才暴露 | ✅ 本轮修复（改用屏幕的逻辑可用区域） |
| **副屏启动** | `app.main()` / 主窗口 | 用 `primaryScreen()`，**在主屏显示**（不跟随当前鼠标所在屏） | ⚠️ 已知差异 |
| **小屏 / 低分辨率** | `_base_w_for/_base_h_for` | 按缩放取可用区域的 80%–92%，封顶 1180×780；再小就靠 QScrollArea 滚动 | ✅ |
| **高 DPI 下的窗口圆角** | `FramelessWindow` 用 `setMask` | 远程桌面 / 某些驱动下圆角边缘可能有锯齿或黑角 | ⚠️ 已知差异 |
| **深色 / 浅色 / 跟随系统** | `app.resolve_dark()` | Qt ≥6.5 走 `colorScheme()`，否则读注册表 `AppsUseLightTheme` | ✅ |
| **表格内联颜色** | `_reskin_tree()` | 换主题时自绘控件（环形表/折线/雷达）会重取颜色；**表格里用代码写死的颜色**要等该页重新加载才变 | ⚠️ 已知差异（本轮未做，属观感） |

## 九、打包 / 分发

| 差异点 | 说明 | 状态 |
|---|---|---|
| **OpenSSL 库缺失** | `portable.spec` 的 `EXCLUDE_WORDS` 是子串匹配，裸写 `libssl`/`libcrypto` 会连 Python 自己的库一起删 → 打包版 `import _ssl` 失败 → **HTTPS 全废**。已改成只排除 `pyside6\` 下的副本 + 过滤后强制补回 + 不 UPX | ✅ 上一轮修复 |
| **两条构建路径漂移** | `build.bat` 里手写了一份 PyInstaller 参数，**没有 SSL 兜底与体积瘦身规则** —— 用它打出来的 exe 会重现 HTTPS 故障。本轮已改为统一调用 `build_exe.py` | ✅ 本轮修复 |
| **Web 端未打进 exe** | `portable.spec` 的 `datas` 只有 `rules.json`；`web/` 目录没打。GUI 版不受影响（`app.py` 不读 `web/`）；但用打包产物跑 `python server.py` 式的 Web 模式会 404 | ⚠️ 已确认无影响（Web 模式是开发期用法） |

## 十、结论

- **必须依赖具体硬件的功能，基本都做了「拿不到就退回 / 明说不可用」的处理**：温度三级兜底、GPU 无独显回退聚合、无 EDID 跳过、无电源计划不崩。
- **本轮修掉的跨机型问题**（都是"换台机器才暴露"的类型）：
  1. 非混合架构 CPU 上「绑到 E 核」实际绑了全部核（`set_process_affinity`）
  2. 繁体系统 regedit 定位失效（`_user_reg_root_label`）
  3. 启动窗口在非 100% 缩放下跑出屏幕（`SplashWindow._center_on`）
  4. 两台同型号显示器少显示一台（`monitors` 去重键）
  5. PowerShell 偶发失败被永久缓存 → 该页整会话空白（`sys_basic` / 主板 / 内存条 / 显存）
  6. PDH 不可用的机器网络一直显示「准备中」（`_net_loop_fallback`）
  7. HKU 路径被当 HKCU 读（`reg_read`）
  8. "当前生效电源计划"依赖 powercfg 输出格式（`cpu_plans`）
  9. EPP 首次读取失败后永不重试（`_powercfg_set_hidden`）
  10. `sc.exe` 被安全策略拦 → 改用 advapi32 直读（`service_state`）
- **仍然存在的差异**（不影响功能，或属设计取舍）：多处理器组 >64 核、WiFi 压过有线成为"主网卡"、副屏启动仍开在主屏、核显无温度、缩略图缓存文件名硬编码、表格内联颜色换肤滞后。
