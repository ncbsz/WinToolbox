# v1.4 详细更新日志（从 README 拆出）

> README 的 v1.4 段已按要求压缩到 300 字以内，这里是**原完整版**，保留所有细节备查。

**修复**

- **「全关闭 Defender」现在有进度反馈**：要写 8 个服务/驱动 + 4 个策略键 + 4 个计划任务，
  逐个回读复核要好几秒，以前只显示一句「正在关闭…」，看着像卡住了。
  现在状态栏逐步显示「禁用服务/驱动 3/8：WdNisDrv（驱动）…」这类文案。
  - 后台线程只写进度文本，主线程用 120ms 定时器采样显示 —— **不跨线程碰控件**，
    操作结束立刻停表（不常驻）。
- **配置档案再补一块：启用/禁用记录**（启动项 / 服务 / 计划任务）：
  - 禁用这三样改的是 **Windows 自己的状态**（`StartupApproved` 标志 / 服务 `Start=<n>` / 任务的 Enabled），**系统里没有「谁禁的」这种线索** —— 换台机器那边只会看到「都是启用的」。
  - 现在本工具每次禁用都会在自有子树 `HKCU\Software\WinToolbox\DisabledByTool` 记一笔（启用时删掉），随配置档案一起走。
  - 导入时**按本机实况算差集**，只列「本机还没禁用的」，再单独问一次要不要照做；取消则一项都不动。
  - Defender 自己那 4 个计划任务不进这份通用记录（它有自己的快照/还原逻辑）。
- **Defender 状态改说结论**（用户反馈：全关闭之后看着像没生效）：
  - 全关闭要动 8 个服务/驱动，旧版只写「7/8 已禁」，差的那一个用户看不出是什么。
  - 现在药丸直接给结论「已实际关闭」，下面另行写明 `WaaSMedicSvc` 会被 Windows 的更新医疗**定期改回手动** —— 属正常现象、不影响实际关闭，不是本工具没写成。
  - 真有没禁成的才会写「⚠ 仍未禁用：… —— 需进安全模式再执行一次」。
  - `defender_status()` 相应新增 `self_heal` / `sticky_remaining` / `effectively_off`（读不到时是三态，不退化成「已关闭」）。
- **配置档案带上「已生效优化项清单」**（用户反馈：用备份文件一键调系统，覆盖不了已优化项）：
  - 档案新增 `optimize_applied` —— 导出时**按系统实际状态**算出的已生效项 id（不是勾选状态，勾选本来就不该跟着走）。
  - 导入时按本机实测算出「还差哪些」，**单独问一次**要不要补齐；确认后走 `snapshot_and_apply` 补齐（自动记录原值，可用「撤销上次优化」回退）。选「取消」则一个字节都不改。
  - 卡片说明与导出提示里都写明「档案带走的是当时**真正生效**的项」。
- **注册表清理：不再只给 400 条**
  - 上限下拉新增「不限」；**只勾一个小类时自动放开上限**（选了某一类就该看到它的全部条目），并在结果区写明「已自动放开」。
  - 结果被截断时**明确写出来**：① 有分类正好卡在每类上限、② 总数超过全局上限、③ **枚举阶段就被读取上限卡住**（最隐蔽的一种，以前完全不提示）。
- **显卡伪装：改了名字但设备管理器 / 任务管理器没变**
  - 写入位置从 1 处扩到 3 处：类键 + 设备实例的 `DeviceDesc` / `FriendlyName` + `Control\Video`（设备管理器读的是设备实例那处）。
  - 支持 REG_BINARY 类型的名字值（Intel 核显是 UTF-16LE 二进制，以前被跳过，只改了一半）。
  - 备份写入失败不再静默吞掉；一个都没写成时会回退备份。
  - 每次写入后回读复核，结果按位置逐条列出（以前只显示前 4 条，关键那条被吞）。
  - 新增「重启显卡」按钮：只重启所选的那一个显示设备（`pnputil /restart-device`），不用重启电脑。
  - 新增「系统现在报的名字」按钮，可直接核验是否生效。
  - 新增显示名清洗：预览里用尖括号做加粗，如果把预览文本原样粘回输入框，
    尖括号会被写进注册表（设备管理器会显示成带符号的字面）。现在粘贴时自动洗掉
    HTML 标记与实体；名字超过 80 字也会在写入前拦下。
- **配置导出升级成「完整档案」，并合并成一张卡**（用户反馈：导出 json 换新电脑后**没能把所有设置恢复过来**）：
  - 根因：原来只导出 `settings.json`，而它只含**外观与偏好**。右键菜单禁用、系统组件禁用这些**功能状态存在注册表里** —— 换了机器就丢了。
  - 现在导出的是**单个档案文件**（带 `_app` / `_format` / `_version` / `_exported` 标记），里面含：设置 + **本软件自有注册表状态**（`HKCU\Software\WinToolbox` 整棵子树，REG_DWORD / REG_SZ / REG_BINARY / REG_MULTI_SZ 都按原类型往返）。
  - 导入流程照 TweakHub 的做法：**先整份校验**（不合格就一个字节都不动）→ **先给当前配置留一份恢复副本**（写到 `backup/profile_before_import_*.json`）→ 应用 → 报告（含注册表写回了多少键/值）。
  - **兼容旧格式**：老版导出的平铺 `settings.json` 照样能导入，且会明说「这是旧版文件，只含设置」。无关的 json 直接拒绝（不硬套）。
  - 导入是**叠加**：档案里有的键覆盖，没有的保持本机原样。
  - **不含**显卡改名备份、Defender 原始状态快照、操作日志 —— 那些属于**本机**（分别在「导出」提示和卡片说明里写明）。
  - 设置页原来的「自动备份」与「导入 / 导出」两张卡**合并成「配置备份与迁移」**。
- **修复「导入设置后没有任何改动效果」**（用户反馈）：
  - 根因：`import_cfg()` 只把数据写进 `settings` 字典，**没有把设置应用到界面** ——主题、强调色、各页控件都不会跟着变，看着就像没导入。
  - 现在导入后会：重应用主题与强调色（`set_theme_mode` / `set_accent`，它们靠 QSS 重画）、广播给所有已加载的页重读、同步本页控件（开机启动 / 关闭行为 / 检查更新）、并顺带同步跨页设置项（软件管理的「静默卸载」、清理页的「文件年龄」）。
  - **只应用导入文件里确实带了的键** —— 免得把本机原有的主题/强调色重置掉。
  - 「恢复上次设置」也走同一套（之前同样少了重应用主题这一步）。
- **修复 `.reg` 备份还原的三个缺陷**：
  - **按键计数 → 按值计数**：原来只要键建成了就算「已还原 1 个键」，空值的键（如只有删除标记的 `[-HKEY_…]`）**一个值都没写也报成功**。
  - **加了回读复核**：写完全部读回来比对，不一致计入失败（不再信「没抛异常就是写成功」）。
  - **类型不认识的值不再静默跳过**，逐条写进结果；值类型不匹配也抓（winreg 抛的是 `TypeError`）；文件不存在时明确报「不存在」。
- **电源计划：加了「被外部改动」提示**（用户反馈「打开软件时计划被改成高性能」）：
  - 实测（启动 + 遍历全部页面，打桩注册表写入与全部子进程）确认：**本软件只查询、不切换**，`setactive` 只出现在用户点击的处理器里。
  - 但现象确实存在，所以现在**启动时只读记一笔当前计划**；运行期间若它变了、又**不是在本软件里点的切换**，电源页会如实提示「是别的程序（厂商控制中心 / 系统自己等）改的」，并说明怎么切回。
  - **只提示、不自动改回去** —— 替用户动系统状态是更糟的做法。
- **「Windows 修复菜单」卡片从「CPU 调试」搬到「设置」页**（用户要求）：
  - 它本来就是**系统级修复入口**，不是 CPU 功能 —— 放在设置页和「关于」挨着更合理。
  - 卡片和它的处理逻辑（`go_recovery` / `_reboot_ui` / `_reboot_done` / `_paint_reboot` / `_reboot_tick` / `do_cancel_reboot` / `_cancel_done`）**整体搬迁**，CPU 页不留残件。
  - 功能不变：二次确认 → 下发 `shutdown /r /o` → 30 秒倒计时（随时「取消重启」）→ 失败如实报错并给出可手抄的命令。
- **卡片改成「Windows 修复菜单（「高级启动」）」，E-core 相关的东西全删了**（用户要求）：
  - 这张卡现在**只有一个功能**：重启进入 **Windows 恢复环境** —— 就是「电脑多次启动失败后自动跳出来的那个修复界面」。（`shutdown /r /o`、Shift+重启、「设置 → 系统 → 恢复 → 立即重新启动」进的是**同一个环境**，只是入口画面不同：多次失败会先显示「自动修复」。）
    里面有：**启动修复**、**启动设置**（可选安全模式）、**系统还原**、**命令提示符**、**UEFI 固件设置**。
  - 卡片 = 标题 **「Windows 修复菜单（「高级启动」）」** + 一句说明 + **蓝色的「重启进入「高级启动」」**按钮 + 「取消重启」（默认禁用，只在倒数 30 秒里可用 —— 否则点完就撤不回来了）。
  - **删掉的**：E-core 状态行、「禁用 E-core」「恢复全部核心」「自检」三个按钮、原理 / 风险两段说明、`server` 侧全部 `ecore_*` 函数、`tests/smoke_ecore.py` 整个套件，以及「重启进入 UEFI 固件设置」（`/fw`）那条路。
  - 重启机制本身保留（`reboot_to` / `cancel_reboot`）：**刻意不加 `/f`**（有未保存文档时让系统自己提示）、留 **30 秒倒计时**并给「取消重启」；`shutdown` 失败时把原因写在输出里，所以**不只看返回码**。
- **统一说明文字（notice）的垂直排版**（用户反馈「文字高度统一一下」）：
  - 根因：`QLabel` 默认是 **垂直居中**（`AlignLeft | AlignVCenter`），而 notice 有 12px 上下 padding —— 框一旦比文字高，文字就悬在中间，上下各多一截留白；不同 notice 行数不同、多出的量也不同，看起来就是「行距 / 留白不统一」。
  - 两处改动：① `notice()` 固定成 **左上对齐**，文字一律从 padding 之后开始；② 系统优化的两张开关卡片末尾补 `addStretch(1)`，卡片被等高拉伸时多余空间落在**底部**，不再把中间的说明框撑高。
  - 实测：全 17 个页面共 32 个可见 notice，**高度都正好等于内容高度**（1 行 = 48px、2 行 = 64px、4 行 = 101px），上下留白一致。
- **「系统优化」的大类改成一行三个横排**（原来是单列长条）：
  - 图标 + 名称 + `›` 一行，下面一行写「N 项 · 已生效 M」，有勾选时再加一枚「已勾选 N」的药丸。与「清理与诊断」hub 页**同一套卡片写法**（复用既有的 `CatCard / CatIcon / CatName / CatSub / CatArrow` 样式，没有新造 QSS）。
  - 14 个大类正好铺成 5 行（末行 2 个），三列等宽、同行等高；多出来的纵向空间留给末尾，卡片不会被摊开拉高。
  - 点卡片进大类、点「‹ 返回大类」回来，行为不变。
- **磁盘占用扫描：实时大小 + 只展开主文件夹 + 搜索 + 原生右键菜单**：
  - **边扫边显示**：每扫到一个大文件夹立刻出现，大小**跟着进度实时变化**（先给中间值，扫完收敛到最终值）。实现是「每累积若干个文件就往祖先链推一次」，不是每个文件都往根走一遍（整盘百万文件会明显拖慢）。
  - **搜索框**：按名字搜文件夹 + **大文件名**（大文件在扫描时顺手记下，不用第二次遍历）；点搜索结果里的文件夹会直接展开到它那一层。
  - **右键菜单只给系统原生项**（打开 / 定位 / 复制路径 / 复制 / 剪切 / 快捷方式 / 重命名 / 删除到回收站 / 命令提示符 / PowerShell / 属性），云盘与编辑器等第三方项一律不放。
  - 顺带修了树的两处：① 树形表格**关掉全局排序**（排序会让父子行错位，改成同级降序）；② 真实路径单独存，别拿列里显示的带缩进文字当路径用。
- **修「打开软件会改我的电源计划」**（用户反馈，已定位到根因）：
  - 排查办法是**仪器化**：把 server 侧所有写入口（`reg_write` / `reg_delete` /
    `set_task` / `_svc_set_start` / `cpu_set_state`…）和 `run()` 里的写命令
    （`powercfg -set*` / `-attributes`、`reg add`、`sc config`、`schtasks`、
    `netsh`、`bcdedit`）全部打桩成「只记录不执行」，再建一次窗口泵事件。
  - 结果：**启动本身是干净的**；但**一进「电源管理」页**就会跑
    `powercfg -attributes SUB_PROCESSOR <EPP> -ATTRIB_HIDE`
    —— 为了让 `powercfg -q` 能读出 **EPP（能效偏好）**，先把该设置从「隐藏」
    改成「显示」。而 `-attributes` 是**写进当前生效计划**的，等于替用户改了计划。
  - 而且**本机实测那个计划里 EPP 根本没设过**（`SUB_PROCESSOR` 下只有 3 个设置），
    解除隐藏纯属副作用、一点用都没有（去掉之后 EPP 照样读得到）。
  - 已**彻底删除**这个动作；读不到就如实显示「未设置（用默认）」。
    `cpu_set_state()`（用户主动设置）里那一处也一并去掉 ——
    `-setacvalueindex` 对隐藏设置照样写得进去，「隐藏」只影响经典电源对话框里的可见性。
  - 新增 `tests/smoke_no_autowrite.py` 守住：**启动 + 逐页进入，
    出现任何写命令即失败**（15 个冒烟套件之一）。
- **二级页都加上了「返回」入口**：从大类进去的页（「清理与诊断」下的垃圾清理 /
  注册表清理 / 系统组件 / 策略诊断）现在顶部栏会显示
  「**← 返回清理与诊断**」，点一下回到大类。
  - 放在**顶部栏统一实现**，而不是各页自己加 —— 一处实现，以后新增二级页
    自动就有，样式也统一；各页自己加迟早漏一两个。
  - 一级页（概览 / 设置…）和大类页本身不显示该按钮，切页时自动隐藏，不残留。
  - （「系统优化」页的「大类 → 条目列表」本来就有「‹ 返回大类」，保持不变。）

- **磁盘占用分析改成「只列主文件夹，点击才展开子级」**：
  - 原来是一张**平铺的大表**：整盘几十万个目录全铺出来，一边扫一边往里插行，
    根本没法看。现在只列**主文件夹**，点一行（或行首的 ▸）才展开它的子文件夹，
    一层一层往下看。**同级按占用降序** —— 树形表格不能开表头全局排序
    （一排序父子行就错位），排序改成「同级排」。
  - 行的颜色、`▸`/`▾` 箭头、缩进都会跟着变了；没有子目录的行不给箭头。
  - **扫描到全部扫完才结束**：完成态明确写「✓ 扫描完成 · 共 N 个文件夹 /
    N 个文件 / 合计 X / Y 秒」，不再让用户对着一个还在变的列表猜。
  - 「在资源管理器里定位」改用行上存的**真实路径**（列里显示的文字带了缩进和
    箭头，不能当路径用）。
- **新增「清理与诊断」大类**：垃圾清理 / 注册表清理 / 系统组件 / 策略诊断
  这 4 个页不再单独占侧栏一项，收进一个新的「清理与诊断」大类里 ——
  进去后**一行三个格子**，点格子进对应页。侧栏从 16 项减到 13 项。
  - 这 4 个页**功能一点没少**，只是入口换了；进去后侧栏高亮会停在本大类上，
    点「清理与诊断」就能回来（不会出现「整列没有一项高亮」的空状态）。
- **修「深色主题下文字看不见」**（系统组件页尤其明显）：
  - 根因是代码里用了**调色板里不存在的颜色名** `FG` / `MUTED`，
    `get_color()` 找不到就兜底返回 `#000000`。浅色主题下黑字压白底看着正常，
    **深色主题下黑字压近黑底（#121826）= 完全隐形**。正确名字是
    `TEXT` / `TEXT2` / `TEXT3`，已全部改正（6 处）。
  - 兜底也改成返回主题正文色 —— 以后再打错名字只会「显示成普通文字」，
    不会再看不见。真正的防线是审计里新增的断言：
    **所有用到的颜色名必须都存在于调色板**。
  - 顺带做了全页面的表格文字对比度体检（深/浅两套主题，阈值 3.0），无低对比项。

- **后台读取失败不再静默吞掉**（项目铁律「失败 ≠ 没有 / 读不到 ≠ 正常」）：
  - 原来有 **14 处** 显式传 `on_fail=lambda *_: None`（= 主动选择静默）。
    逐个读源码 + 调用点后分成两类：
    - **刻意静默 8 处**：6 处是 1 秒级轮询（弹提示会变成每秒一次骚扰）、
      1 处是启动预热（结果本来就丢弃）、1 处是自动检查更新
      （docstring 写明「失败零打扰」）。这 8 处**都在代码里标了**
      `# 刻意静默：<理由>`。
    - **真正要修 6 处**：概览「详细信息」的硬件信息、CPU 调试的进程调度状态、
      电源管理的计划列表与所选计划参数、显卡伪装的目标显卡列表、
      注册表清理的「已禁用右键菜单项」列表。
      现在失败时会写「**读取失败：<读什么>（<原因>）**」并标警示色，
      而不是留一个「—」或空表让用户以为「本来就没有」。
  - 新增 `Page.load_fail(label, what, msg)` 作为统一出口。
  - 审计断言收紧到最强：**不允许存在未标记的静默点** ——
    以后任何人新增一个静默失败，都必须写明为什么可以静默。

- **「关闭更新」改成「暂停更新到 2099 年」，不再禁用服务**：
  - 原来是「禁用 wuauserv / UsoSvc / WaaSMedicSvc 三个服务 + 写
    `NoAutoUpdate=1`」。这做法问题很实际：
    · **不可逆的副作用** —— 服务被禁之后，驱动更新器、企业的补丁基线检查
      会看到「更新服务不存在」而报错，用户自己却根本不知道；
    · 一旦禁了，「恢复」得靠重写 Start 值 + 重启才能完成，中间那段时间
      是**裸奔**的（补丁完全收不到，而且没有任何提示）；
    · 写 `NoAutoUpdate=1` 还会和域环境 / 企业策略冲突。
  - 现在改成走 Windows 自己那条路：**只往 `UX\Settings` 写三个
    `Pause*EndTime = 2099-12-31`**，也就是「设置 → 更新 → 暂停更新」
    按钮干的事。系统完全认可，「暂停更新」会真的显示成暂停到 2099-12-31。
  - **实测验证**：点完「暂停更新」，三个服务的 `Start` 值**一个都没变**，
    `NoAutoUpdate` 也没被写。恢复只需清掉这几个值，**立即生效、不用重启**。
  - **「恢复更新」仍会顺手收拾旧版本的残留** —— 它同时把服务 Start 值
    恢复默认、删掉 `NoAutoUpdate`。因为本工具的旧版本（以及第三方工具、
    用户手改）可能已经禁用了服务；只清暂停的话服务还禁着，
    用户会以为「点了恢复还是收不到更新」。
  - 状态显示改成四态而不是两态：正常 / **已暂停到 2099-12-31** /
    服务被禁 / 普通暂停。以前「已开启（已暂停）」这种自相矛盾的说法
    会让人以为更新在正常工作。
  - **修复「暂停之后点恢复没反应」**：按钮文案的判据和点击动作的判据不一致 ——
    按钮看「有没有暂停/异常原因」写「恢复更新」，而点击算的是
    `not 服务是否放行`。因为「暂停」**不碰服务**，那个值仍是 True，
    于是点下去又执行了一次**暂停**。现在两者读同一个 `_upd_suppressed()`，
    从结构上杜绝这种背离。
  - **文案精简**：卡片说明只说「会把 Windows 更新暂停到 2099 年」，
    确认框同样去掉技术解释 —— 用户要的是「会发生什么」，不是原理。

    「已处理干净」，用户以为清完了。
  - 现在 4 处全部改走 PowerShell 的 `ScheduledTasks` cmdlet：
    枚举 `Get-ScheduledTask`、启停 `Enable-/Disable-ScheduledTask`、
    删除 `Unregister-ScheduledTask`。

- **修复「刷新」按钮点了没反应**（软件管理 / 启动与服务 / 显卡伪装三处）：
  - 这些按钮绑的是 `refresh()`，而它走会话缓存 —— **第二次点会直接回放上次的旧数据**，
    列表纹丝不动，看起来像按钮坏了。真正该用的是 `reload()`：先丢缓存再重读系统。
  - 现在五处「刷新」按钮全部改绑 `reload()`，点一次就真读一次。
  - 顶层工具栏那个刷新本来就是对的（走 `page.reload()`），没动。
- **修复「系统还原点读得到但删不掉」**（注册表清理 → 备份与还原）：
  - 根因是**命令名从一开始就是错的**：Windows **根本没有 `Remove-ComputerRestorePoint`
    这个命令** —— SystemRestore 模块只提供 `Get-ComputerRestorePoint` 和
    `Checkpoint-Computer`。旧代码调的是一个不存在的命令，PowerShell 报「找不到命令」
    就完事，一个都没删；回读发现还原点还在，于是界面报「删除未生效」，看着像功能坏了。
  - 正确途径：`Get-ComputerRestorePoint` 返回的对象本身带 `Delete()` 方法，对它调用即可。
  - **顺带修掉一个更隐蔽的坑**：判定成败不能只看 PowerShell 的退出码 ——
    WMI 抛错时**退出码仍然是 0**；原来那句 `; 'OK'` 哨兵也是假的
    （实测 `Checkpoint-Computer` 失败时 stdout 里 `OK` 和报错**同时存在**）。
    现在改成 `try { ... 'SRP_OK' } catch { 'SRP_ERR:' + $_.Exception.Message }`
    配 `-ErrorAction Stop`，成功标记与失败原因**互斥**。
  - 失败原因现在是**中文**且具体：「没有权限（需要以管理员身份运行本程序）」而不是
    一句 `Access denied`；「序列号已不存在」和「删除失败」也分开报了。
  - 如果 `.Delete()` 没抛错但还原点还在（最典型是**最早的那个还原点 Windows 不允许删**），
    界面会直接说明这是系统限制，不会让你以为是 bug。

  - **为什么不做实时监控**：Windows 原生没有「谁动了这个文件」的系统级监视（ReadDirectoryChangesW 只有变化通知、没有**进程归属**），要精确归属必须上 minifilter 驱动或 ETW 内核会话 —— 那要驱动签名、有蓝屏风险，代价与收益不成比例。快照对比同样是通用做法。

- **卸载时自动做「精确对比」**（把上面这套快照机制接到卸载流程上）：
  - 卸载**前**除了按名字找相关文件，还会拍摄**该程序安装目录的快照**；卸载**后**重扫对比 → 卸载**没删掉**的文件会被逐条列出，标为「**该删没删**」。
  - **为什么这比原来的名字匹配准**：名字匹配要求路径「得像」程序名（`FooBar` → `Foo`），像 `small1.txt`、`{GUID}`、`Common Files\Foo` 这类**名字完全不像**的残留它找不到；而快照对比只看**这个文件在不在**，不管它叫什么。实测：删掉 7 个 `smallN.txt` 后，剩下的 3 个 `bigN.dll` 被精确检出、已删的**零误报**。
  - **为什么只对安装目录做、不做全量**：实测 Program Files 全量拍一次 1.8 秒（11 万文件）还行，但加上整个 `%LOCALAPPDATA%` / `%APPDATA%` 要 **20.3 秒**（47 万文件）—— 用户要干等 20 秒才能开始卸载，不可接受。而且 Program Files 里本来就有**别人的**文件，「仍在」根本不能当残留；只有**该程序自己的安装目录**里「仍在」才等于「该删没删」。
  - 两种边界都不刷屏：卸载**一个文件都没删**（说明没真正卸载）时只做目录级提示；**全删干净**时不报任何东西。

  - **无效项清理**：无效文件关联（默认打开程序 / 选定打开方式已卸载）、无效 AppID / TypeLib / 代理存根引用、启动项指向的程序不存在、防火墙规则指向的程序不存在。**每项删除前自动导出 .reg 备份，备份失败直接不删**，删完回读复核；低置信项（候选打开方式、防火墙规则）默认不勾
  - **右键菜单管理**：枚举文件 / 文件夹 / 文件夹背景 / 驱动器四类扩展菜单，区分第三方与系统自带（按处理器 CLSID 的 InprocServer32 是否在 SystemRoot 下）。**禁用不是删除** —— 整棵子树搬到 HKCU 备份区并记录，随时一键还原
  - **备份与还原**：系统还原点的列出 / 新建 / 删除（需管理员），删除后回读复核；默认全部不勾（删除不可撤销）。非管理员读不到时明确提示「需要管理员权限才能读取」，**不谎报「0 个」**
  - **快捷方式修复**：COM 批量读桌面与开始菜单的 .lnk，标出目标已失效的；修复时在已装程序安装目录与 Program Files 里找同名 exe 并重建指向

**优化 / 修复**

- **卸载改为「等自带卸载程序关闭」之后才扫残留**：
  - ⚠️ 原实现只看 `Popen` 的那个进程 + 注册表键，两个都不准：
    · 卸载器普遍**先自我复制到 `%TEMP%` 再重启**（NSIS 的 `Unins000.exe`/`Au_.exe` 就是这个套路）→ 父进程瞬间退出，被误判成「已结束」，在用户还没操作完时就去扫残留；
    · 注册表键先被删、进程还在清文件 → 此时扫到的是一堆「还没删完」的正常文件。
  - 现在以**「卸载程序进程全部关闭」为主判据**：按「进程名 == 卸载程序 exe」「进程 exe 落在安装目录内」「卸载程序同目录下的其它可执行文件」三个信号找，MSI 则只看进程句柄（`msiexec.exe` 是全局公共宿主，按名字匹配会误判）。
  - 关闭之后再看注册表键，据此区分三种结果：**completed**（真卸载完了 → 自动进入残留扫描）/ **cancelled**（键还在 = 用户取消了 → 不自动扫，避免扫出一堆正常文件，并明确告知）/ **timeout**（一直没关，可能弹了 UAC 或窗口被最小化 → 如实提示后由用户决定）。
- **修复「卸载残留扫描里空文件夹不显示」**（两个独立原因）：
  - ⚠️ 原因一：残留目录靠 `_orphan_dir_evidence()` 的**证据链**判定 —— 必须存在一条「已失效的 ARP 记录」指向它。但程序被**完全卸载**时 ARP 记录会一起消失，此时留下的空文件夹**没有任何证据可依**，于是永远不显示。而「卸载完只留一个空文件夹」恰恰是最常见的情形（本机实测：350 条 ARP 里只有 1 个目录能被证据链捕获）。
  - ⚠️ 原因二：`%LOCALAPPDATA%\Programs`、`C:\Program Files` 都在**免疫名单**里（删除时必须挡住），而原代码在扫描时对它直接 `continue` —— **整棵 `Programs` 子树都不看**，本机实测漏掉全部 120 个。受保护 ≠ 不能往里看：现在受保护目录本身永不上报，但允许在第一层往里下钻。
  - 解法（「搜索词 × 搜索路径」思路，取更保守的版本）：新增`_leftover_empty_dirs()` —— 只报**完全不含文件**的目录（删掉不可能丢数据），且不属于任何在装程序、不在跳过名单里。结果标 low-confidence（默认不勾选）。
  - **跳过名单刻意收得比较严**，避免把系统目录当成「残留」而伤可信度：`PlaceholderTileLogoFolder`（系统磁贴缓存，本机占十几条）、`Templates`、`VirtualStore`、`DBG`、并按**路径段/词**过滤 `Microsoft` / `NVIDIA` / `Adobe` 等；尤其 **`Package Cache` 必须跳过** —— 那是 MSI 的安装包缓存，删掉会导致程序无法修复和卸载。过滤后本机 60 条候选、0 项误报。
  - **降噪**：空残留目录若路径里命中「仍在装程序」的特征词（`ProgramData` 下的 `ASUS\Virtual Pet`、`Local` 下的 `Tencent\QQ` 这类），说明归属厂商还在装机上、有主就不是孤儿，直接跳过。
    本机实测 **147 条 → 120 条**，砍掉的全是同厂商空壳。
    （厂商在装 ≠ 该子目录不是残留，所以这只是降噪；被跳过的目录在
    「磁盘工具 → 空文件夹清理」里仍能找到。）
  - 列表里现在会带上来源标签（`[空残留目录] C:\...`），且 low-confidence 项的提示语按**原因**区分（空目录 ≠ 名称片段相同）。
- **修复「卸载时调不起软件自带的卸载程序」**（根因是取错了字段）：
  - ⚠️ 代码里写的是 `cmd = QuietUninstallString or UninstallString` ——**优先静默卸载**。而 `QuietUninstallString` 是不弹任何界面的静默命令（典型：7-Zip 的 `Uninstall.exe /S`），于是点完卸载什么都看不到，只能干等它静默跑完；而确认框偏偏写着「会弹出它自带的界面」，**文案与实际行为正好相反**。
  - **本机影响面：348 个程序里有 66 个同时带这两条命令**，全都会被静默卸载。
  - 已改为 **`UninstallString` 优先**（调用程序自带的卸载向导），只有在确实没有交互式命令时才退回静默；确认框文案也按实际方式区分。
  - 顺带复核了卸载链路本身：348 个程序的命令解析 **0 失败**（160 个 exe 存在、126 个 MSI、1 个真残留、61 个无命令），说明解析与启动没问题，问题只出在「选哪条命令」。
- **修复「空文件夹清理扫不出东西」**（根因是扫描逻辑提前跳过）：
  - ⚠️ 原实现里有一句 `if has_file: continue` —— **只要当前目录直接含文件，就跳过整棵子树**。而 `D:\桌面`、`D:\文档` 这类目录第一层就有文件，于是里面成千上万个空文件夹一个都报不出来。**本机实测只扫出 1 条、耗时 0.0 秒**。
  - 正确逻辑：**不管自己有没有文件，子目录都要继续查**（自己不是空的不代表子目录不是空的）。现在本机扫出 **200 条**（触顶上限）。
  - 另加 `max_visit` 上限，防御几万个目录的极端目录树拖死扫描。
- **修复「用户目录解析」静默失效**（连带影响空文件夹/重复文件/占用分析）：
  - `known_folder()` 的映射表**键名大小写敏感**且只有 Desktop/Downloads/Documents三个 —— 调用方传小写就静默拿到空串，于是退回 `%USERPROFILE%\Desktop`。在「桌面/下载/文档被重定向到其它盘」的机器上（本机就是：`D:\桌面`/`D:\下载`）会指向不存在的路径、**静默扫 0 个**。
  - 已改为大小写不敏感、补全 Pictures/Videos/Music 的 GUID、并加结果缓存（`SHGetKnownFolderPath` 是 COM 调用，扫描循环里反复问很浪费）。
  - 修复后本机正确解析：`pictures → D:\照片`、`videos → D:\视频`、`music → D:\音乐`（后者此前完全没有映射）。
- **修复系统还原点在非管理员下显示成「0 个」**：`Get-ComputerRestorePoint` 在非管理员下返回 `Access denied`，服务端拿不到结果就返回空列表，界面于是显示「0 个还原点」—— 而其实是有、只是读不到。现在会明确提示「需要管理员权限才能读取」。
- **垃圾清理新增「文件年龄」阈值**（修掉一个会**误删文件**的隐患）：
  - ⚠️ **原实现不看文件年龄**：`clean_junk` 遍历目录下**所有**条目直接删（目录走 `shutil.rmtree`）。程序刚创建、过几秒才去读的临时文件会被当垃圾清掉 ——被占用的只是「删失败」计数，**没被占用但正要用的就直接没了**，现象是某个程序莫名报错，极难联想到是清理工具干的。
  - **本机实测体量**：`%TEMP%` 在「不限年龄」下有 417 MB / 5373 个文件，按 24 小时阈值则是 122 MB / 5186 个 —— **差的 295 MB 全是 24 小时内的新文件**，也就是旧版会多删的那部分。
  - 现在只清**够旧**的文件：临时文件 24 小时、内存/崩溃转储与错误报告 48 小时（取保守的安全阈值）。**扫描与清理共用同一套过滤**，所以预览的体积与实际删掉的东西完全一致。
  - 清理页新增「文件年龄」档位：**仅清理 1 天前（默认推荐）/ 2 天前（更保守）/ 不限制**（恢复旧行为）。每项的「说明」列会写明它自己的阈值。
  - 清理完成后会**如实报出保留了多少个较新的文件**，不会让你以为漏清了。
  - 回收站是例外：系统只提供整体清空，无法按时间过滤，所以勾选它会清掉其中全部内容 —— 界面上已注明，且它默认不勾选。
- **修复概览页在小屏/高缩放下出现滚动条**（`1366×728` 溢出 58px、`1280×690` 缩放 150% 溢出 87px；另外 3 个尺寸本来是好的）：
  - **根因**：中排「详细信息」的 8 行值是多行文本（显卡名、显示器型号、网卡名都会折行），卡片 sizeHint 涨到 413px。而 **QVBoxLayout 在「各区块 sizeHint 之和已超过可用高度」时就不再按 stretch 分配**，于是一整页被顶出视口。
  - **踩到的坑**：先试了 `QSizePolicy.Ignored` —— **无效**。它只影响 widget 能否伸缩，`QWidgetItem::sizeHint()` 依旧返回内容高度，布局照样按那个值分配（实测确认）。
  - **解法**：新增 `CardScroll`（`QScrollArea` 子类）**重写 `sizeHint()`，把高度按比例压小**（×0.55，下限 96）。这样一来：小屏时布局愿意压缩它 → 内容在卡片**内部**滚动，整页不再溢出；大屏时省下的空间按 stretch 分回给它 → 照样完整显示 8 行、**不出现卡内滚动条**，视觉与修复前完全一致。
  - 同时把「性能状态」雷达的可压缩下限从默认的 200 降到按缩放计算 （原默认会把卡片最小高度锁死在 244px，是小屏的第二个溢出源）。
  - 多配置布局回归从 **196/200 提升到 200/200**。
- **修复「电脑是否开启更新」识别错误（读取的参数不对）** —— 三个缺陷：
  - ⚠️ **只读 `wuauserv` 服务的 Start 值，完全没检测「更新被暂停」**。本机实测：`wuauserv=2`（看起来完全正常），但`UX\Settings\PauseUpdatesExpiryTime = 2026-11-07`（未来时间）→ **更新被暂停，根本收不到任何补丁**，而旧实现照样报「已开启」。这正是「我明明没关更新，为什么几个月没打补丁」的典型原因。
  - ⚠️ **漏了一半的禁用手段**：只查了 `AU\NoAutoUpdate`，漏掉`DisableWindowsUpdateAccess=1`（关闭所有更新功能）与`AU\UseWUServer=1`（被企业 WSUS 接管）。
  - **`wuauserv` 的「恢复默认值」写错了**：上一版写成 2（自动），而 Win10 1709 起它实际是 **3（手动 / 触发器启动）** （官方文档口径："Windows Update commonly uses 3 for manual trigger start"）。写成 2 会把「开启更新」调成非默认状态。
  - 现在改为**四层判定**（服务 / 策略 / 暂停 / WSUS 接管），界面用「当前：已开启（已暂停）」+ 红字原因如实说明，并且点「开启更新」会**一并清掉暂停标记**（含回读复核），否则用户点了开启仍然收不到更新，等于没修好。
- **移除「窗口背景不透明度」设置**：该功能靠颜色里的 alpha 通道实现，而窗口开了 `WA_TranslucentBackground`（圆角需要）—— alpha 一降，透出的就是**桌面壁纸**，深色底叠在亮色壁纸上直接「发白」，是结构性缺陷；对照实现之所以没这个问题，是因为用了 DWM 的 **Mica 材质**（由系统合成、透出的是被主题色重新着色后的壁纸），PySide 调不到。与其保留一个必然出问题的开关，不如去掉：现在背景恒为**实心主题色**。同时删净了相关代码（`theme.bg_rgba` / `_map_alpha` / `_ALPHA_MIN`、`build_qss` 的 `opacity` 参数、设置页滑块、`MainWindow.set_opacity`），`AtmosphereArea` 自绘氛围层也改为直接填实心主题色。
- **修复 Windows 更新开关「点了没反应」**：
  - ⚠️ **写入用的是 `reg.exe`，而它被系统安全策略拦截** —— 实际一个字节都没写进去，旧代码只看返回码就当成功，界面照样弹「已关闭更新」（**谎报成功**）。已改为 `winreg` 直写 + **写完立刻回读复核**，任何一项失败都会如实列出是哪个服务、什么原因
  - 界面按你的要求**简化成纯开关**：一个按钮 + 已开启/已关闭两态（识别逻辑的后续修正见上面那条）。**Windows Defender 开关有完全相同的 bug，一并修了**
- **修复「软件管理 → 更新补丁」分类永远空白**：不是权限问题，是**数据源选错了**。旧实现靠 ARP（「应用和功能」）名单里的名字正则匹配 `KB\d+`，但 Win10/11 的累积更新**早已搬离 ARP** —— 实测本机 350 条 ARP 里带 KB 号的**一条都没有**，所以永远筛出 0 条。已改为走权威来源 `Get-HotFix`（CIM 的 Win32_QuickFixEngineering，本机读到 5 条，含安装日期与安装者，缓存 5 分钟）；补丁行有专门的右键菜单（查 KB 详情 / 复制编号 / 搜索），点卸载会明确提示去哪卸
- **修复文件签名校验「全部判成未签名」**：`wintrust!WinVerifyTrust` 的第 2 个参数是 **GUID 指针**，传成 `c_void_p` 整数会被当 GUID 读 → 不报错、静默返回 `TRUST_E_NOSIGNATURE`。`explorer.exe` / `chrome.exe` 这类确有 Authenticode 签名的文件全被误判。已改用真实 GUID 结构 + 失败后补调 `WTD_STATEACTION_CLOSE`（否则状态数据泄漏）

**优化 / 修复**


- **软件卸载与垃圾清理功能扩充**：
  - **垃圾清理补齐到 20 项并分三类**（新增「分类」列：常规清理 / 浏览器缓存分组）：常规清理补 **Windows 系统日志文件**、**字体缓存**、**系统蓝屏转储 (Minidump)**、**Windows 错误报告队列**（全机 ProgramData\WER）；浏览器缓存补 **Firefox / Opera / Brave / Vivaldi**（共 6 款）；系统缓存新增**商店应用缓存**（每个 UWP 包的 LocalCache，通配扫描）。共 20 项，刻意不收 `C:\Windows\Installer`（删了会导致程序无法卸载/修复，风险收益不成比例）
  - **垃圾清理引擎支持通配目录**（`kind:"glob"`）：商店应用缓存 / Firefox 多 Profile 这类「一个模式匹配多个目录」的项，扫描与清理都能逐目录处理
  - **预装应用页新增「重装全部商店应用」**：对所有商店/UWP 应用重新注册（`Add-AppxPackage -Register`，不重新下载），用于修复应用打不开、开始菜单点不动、图标全丢这类损坏；完成后自动刷新并汇报成功/失败计数
  - **软件管理新增「最近安装」分类**：一键过滤最近 30 天安装的程序，排查“最近装了什么搞坏了系统”很快
- **修复「我明明禁用了更新，软件还说可以禁用」**（状态检测与实际不符的一类问题，通查了全部 131 条规则）：
  - **根因一：禁用被系统悄悄恢复**。一键关闭更新会禁 wuauserv / UsoSvc / WaaSMedicSvc 三个服务，但 **WaaSMedicSvc（更新医疗救护服务）之前只被设为"手动"**，它会把 wuauserv 自动改回去 —— 实测本机：策略键 `NoAutoUpdate=1` 还在，`wuauserv` 却被改回了"手动"。现在 WaaSMedicSvc 一并设为**禁用**；`update_status()` 改为**三服务都看**，处于中间态时如实显示「**部分禁用（服务被系统恢复，可再关一次）**」，不再让用户误以为没生效
  - **根因二：等效手段识别不了**。同一个效果可以通过不同路径达成（禁更新可以写策略键，也可以直接禁 wuauserv 服务；关快速启动可以 `powercfg /h off`；设置 App 关传递优化写的是另一个键）。规则引擎新增 **`altChecks`（等效手段）** 机制，命中任一即算"已生效"，已给 5 条规则补上（禁用强制更新 / 更新改手动 / 传递优化 / 快速启动）
  - **根因三：复合字符串整串比较**。「全局显卡首选项」检测的是 `DirectXUserGlobalSettings` 整串相等 —— 你在设置里调过 AutoHDR / 窗口化优化后串里多了参数，就**永远显示未生效**；更糟的是点应用会把整串覆盖成 `GpuPreference=2;`，**把你已有的 AutoHDR 等设置抹掉**。现在按「包含」判定 + **合并写入**（只替换/追加 GpuPreference 段，其余参数原样保留）
  - **根因四：状态缓存不刷新**。优化页的规则状态是会话级缓存，你在软件之外（组策略 / 设置 / powercfg）改过后回来看还是旧的。现在**每次进页都重算**（131 条全量重读实测 <0.5s）；一键开关切换后也会同步失效规则缓存
- **残留清理重做（根治「能删 `C:\Users`」）**：原来的「疑似残留目录」是**负向排除** —— 扫盘根和常见目录、列出「没人认领」的目录，安全性全押在免疫名单上，名单漏一个名字（历史事故就是 `users` / `programdata`）就会被删掉，补名单只是打补丁。现在换成**正向证据链**：
