## 三、横切机制（全项目统一的安全基线）

每一页的写操作都遵守同一条链路：

```
只读扫描 → 列清单 → 用户勾选 → 二次确认（写明处置方式）
→ 先备份 → 执行 → 回读复核 → 如实报结果
```

具体约定：

- **注册表删除**：先导出 `.reg` 到 `backup/`，**备份失败直接拒绝删**
- **文件删除**：走回收站（`SHFileOperationW`）；粉碎才不可恢复
- **卸载**：默认调自带交互式卸载程序，**等卸载器进程真正关闭**才扫残留
- **低置信项默认不勾**（如弱证据的残留目录、候选打开方式）
- **失败 ≠ 没有**：读取失败必须明说，不能安静地留一张空表
- **宁漏勿错**：注册表价值判断拿不准就不判；把活的项当无效删掉会毁掉别人的软件
- **读操作绝不许有写副作用**（用户反馈「打开软件改了我的电源计划」）：
  读取类函数里**不许**出现任何会改系统的命令（`powercfg -set*` /
  `-attributes`、`reg add`、`sc config`、`Set-MpPreference`、
  `*-ScheduledTask` 等）。曾有 `cpu_proc_states()` 为了让 `powercfg -q`
  读出 EPP，先跑 `-attributes ... -ATTRIB_HIDE` —— 那是**写进当前生效计划**的，
  等于用户一进「电源管理」页计划就被改了（而且那个计划里 EPP 根本没设过，纯白改）。
  `tests/smoke_no_autowrite.py` 用「仪器化打桩」守住：
  启动 + 逐页进入，**任何写命令都算失败**。
- **改 settings 之后必须把它应用到界面**（用户反馈「导入设置后没有任何改动效果」）：
  只写 `win.settings` 字典、不重应用主题/强调色、不广播 `notify_all_changed`、
  不同步控件 —— 用户看到的就是「提示成功，但什么都没变」。统一走
  `SettingsPage._sync_from_settings()`；`import_cfg` 与 `restore_now` 两条路径行为必须一致。
  跨页设置项（软件管理的「静默卸载」、清理页的「文件年龄」）也要顺带同步。
- **备份还原按「值」复核，不按「键」**：`reg_backup_restore` 曾按键计数 ——
  空值的键（只有删除标记的 `[-HKEY_…]`）一个值都没写也报「已还原 1 个键」。
  现在逐值回读比对、只按回读一致的值计数，类型不认识的值逐条上报（不静默跳过）。
- **颜色只能用调色板里真有的名字**：`get_color()` 找不到时曾兜底 `#000000`，
  于是「名字打错」在浅色主题下只是变黑字（看着正常），**到深色主题就成了
  黑字压近黑底 = 完全隐形**（`FG`/`MUTED` 就这么坑了很久）。正确名字是
  `TEXT` / `TEXT2` / `TEXT3`。审计有断言：所有用到的颜色名必须都在调色板里。
- **读取失败必须给可见出口**：后台读取失败时若静默留空，用户看到的是「—」或一张空表，
  分不清是「确实没有」还是「读不出来」。统一走 `Page.load_fail(label, what, msg)` 写「读取失败：…」；
  只有 1 秒级轮询 / 预热 / 检查更新这类可以静默，且**必须在代码里写明理由**。
- **二级页必须有「返回」**：从大类进去的页（现为「清理与诊断」下的 4 个）
  由**顶部栏**统一给一个「← 返回 <大类>」——放在一处而不是各页自己加，
  以后新增二级页自动就有，也不会各页样式不一。映射表 `HUB_OF`。
- **按钮文字与点击动作必须同一判据**：抽一个函数（如 `_upd_suppressed()`）两边都读它，
  从结构上杜绝「按钮写着恢复、点下去却在暂停」这类背离。
- **读不到 ≠ 正常**：状态读取失败必须单独表达，不能退化成「默认值」。
  例：Defender 的状态读不到时若报「已关闭」，
  用户会以为防护已经关掉（实际还开着）。用**三态**（True/False/None）表达。
- **说明文字（notice）一律左上对齐**：`QLabel` 默认垂直居中 + notice 有 12px 上下 padding，框比文字高时文字会悬在中间 → 不同 notice 的留白看起来不一致。`notice()` 里固定 `AlignLeft | AlignTop`；被等高拉伸的卡片要在末尾 `addStretch(1)`，别让说明框去吸收多余高度。
- **可逆优先**：能用「暂停」解决的不用「禁用」。「暂停更新」不碰任何服务，
  恢复一下立即生效；禁服务是不可逆副作用，中间那段裸奔期用户自己都察觉不到

## 四、扫描按钮的三态

所有耗时扫描统一走 `ScanCtl`：**开始 → 暂停 → 继续**（12 个扫描入口已接入）。
- `resumable=True`（整盘占用扫描）：真接着扫，不重复累加
- 其余：停住并保留已扫到的结果，「继续」会重新扫一遍（tooltip 已写明）

| 限制 | 影响 | 原因 / 现状 |
|---|---|---|

## 九、被安全策略拦的外部命令（全部已绕开）

本机的「程序黑名单」拦掉了三个系统自带命令行工具。三处都**不是**靠"提示用户
去关策略"，而是换掉了实现方式：

| 被拦的命令 | 用来做什么 | 替代实现 |
|---|---|---|
| `reg.exe` | 导入 / 导出 `.reg` | `winreg` 手工序列化（5.00 格式 UTF-16LE + BOM） |
| `sc.exe` | 服务查询 / 启停 | `advapi32` 直读 + `winreg` 写 `Start` |
| `schtasks.exe` | 计划任务枚举 / 启停 / 删除 | PowerShell `ScheduledTasks` cmdlet |

**共同教训**：被拦的命令会返回**非零退出码且无输出**，如果只判`rc == 0`
就已经算修好了，最坏情况是「界面说成功、实际什么都没做」。所以这三处的替代
实现都补上了**回读复核**——不信「命令返回成功」，只信「重新读一遍的状态」。
