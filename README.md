# WinToolbox 更新日志

作者 by：xixidan ｜ GitHub：<https://github.com/ncbsz/WinToolbox>

## v1.3

**新增**

- **关闭时可选「最小化到托盘」或「直接退出」**：点关闭按钮会问一次，三个按钮
  **最小化到托盘 / 退出程序 / 取消** —— 不想关了直接点「取消」，**或者点弹窗右上角的 ×、
  按 Esc，效果完全一样（都不关闭软件）**。可勾「记住我的选择，下次不再询问」
  （点「取消」时不会记住）；设置页的偏好里也把
  「关闭窗口时」做成了三选一 —— **每次询问 / 最小化到托盘 / 直接退出**。
  收进托盘时会气泡提示「性能监测已暂停」，双击托盘图标即可恢复主界面
- **最小化 / 收进托盘时真正暂停性能监测**：页面侧那些 1 秒轮询本来就由 `page_active()`
  挡着，这次把服务端**两个常驻采样线程（温度 / GPU 占用 / 网络速率）也一起停下** ——
  不是降频空转，是完全静默。实测隐藏窗口 8 秒内**子进程 0 个、网络采样时间戳一动不动**，
  恢复窗口时立即补一次数据（网络速率会先丢一帧重建 PDH 基线，避免恢复瞬间闪一个偏低的
  数值）。**核心调度类设置不受影响** —— 进程亲和性 / 内存·IO 优先级 / 电源计划这些
  都是即写即生效的注册表与 powercfg 写入，不依赖后台线程
- **DNS 测速改为 ICMP ping 口径（对齐 DnsTools）**：原先用「DNS 查询往返」测延迟，
  结果与 DnsTools 对不上（同一台福建电信：ping 10ms 很快，但它的 UDP 53 对跨网来源
  直接丢弃）。现在四类模式（国内 / 国外 / 混合 / IPv6 / 本机 DNS）**统一改用原生
  ICMP ping** 测往返延迟 —— 实测排名与 DnsTools **逐条吻合**（福建电信 10ms、
  CNNIC 15ms、浙江联通 16ms、广东电信 18ms…）
  - 走 `iphlpapi!IcmpSendEcho` 原生 ICMP，**不起 `ping.exe` 进程**（否则 100+ 台要几分钟）；
    IPv6 自动退回系统 `ping -6`
  - 仍保留一次 DNS 查询显示解析结果，并把「**禁 ping 但能解析**」的服务器单独标注
    （如 114.114.114.114）—— 这类 DnsTools 会误报"测试失败"，本工具能区分
  - 实测：123 台里 **ping 通 75 台**（原 DNS 查询口径只有 31 台可用）
- **DNS 测试改为逐条实时显示**：以前要等一百多台全部测完才一次性列出，现在每测完
  一台立刻上屏，状态栏同步滚动显示「已测出 N 个（可用 M）」；全部结束后再按
  「可用优先、延迟升序」重排一次。测试期间「开始测试」按钮置灰，避免重复触发
- **DNS 检测新增「本机 DNS」模式（测通信延迟）**：下拉框多了「本机 DNS」选项 ——
  测的是**本机 ↔ 各 DNS 服务器的通信延迟**：向服务器发查询到收到应答的往返时延，
  **不含服务器向上游递归的时间**，反映的就是本机到这台服务器的链路快慢
  （区别于其它模式的「解析延迟」，后者用随机子域名强制递归，测的是含根/权威链路的耗时）
  - 服务器集 = 本机网卡当前配置的 DNS（用 `ipconfig /all` 读已启用网卡、去重、
    跳过「媒体已断开」，标为**「本机在用」**）+ 内置公共 DNS（国内 / 国外）——
    所以能直接看出「我现在用的这个排第几、换哪个对本机更快」
  - 域名输入框保留，仍作为查询对象；本机没配 DNS 时也照测公共 DNS，不会空跑
  - 做法参照 DnsTools（源码见 `D:\桌面\桌面文件\DnsTools`）的「本机 DNS」思路，
    复用已有的原生 UDP 探测，仅把度量口径换成通信往返
- **右键「定位文件夹」/「复制路径」**：所有列表（软件管理、CPU 调试与内存性能的进程表、
  垃圾清理、启动项 / 服务 / 计划任务、残留与全机扫描结果）右键任意一行
  即可在资源管理器中定位到对应的文件或目录；目录会打开其父目录并高亮它，
  路径已不存在（残留项）则退回定位其父目录。取不到路径的行菜单项自动置灰

  - **右键菜单**（表内任意一行）：卸载 / 修改·修复安装 / **强制删除此条目**

    该条目）/ 访问程序官网 / 用 Google 搜索 / 在 Microsoft Store 中打开；

  - **新增「更新补丁」视图**（对应 Geek 的 Windows Updates），与「全部 / 我安装的 /

  - **列表缓存**：枚举结果内存缓存，切换分类 / 排序 / 搜索不再反复读注册表
  - 与 Geek 的做法一致 —— **卸载始终只调用原厂卸载程序**，不自作主张删文件；
    流程为 记录卸载前快照 → 等卸载真正结束 → 扫描对比 → **逐项勾选**清理

  - **自定义核心绑定 + 强亲和**：勾选任意核心组合绑定到选中进程；勾「强亲和」时还会

- **显卡伪装独立成一个大类**：从 CPU 调试页拆出来，导航新增「显卡伪装」。

- **「扫描卸载残留」整机扫描**（软件管理页，参照 BCUninstaller 的孤儿检测思路，开源实现可查
  `Klocman/Bulk-Crap-Uninstaller` 的 `UninstallTools/Junk`）：
  不需要选中任何程序，直接找整机里**已经失去主人**的东西 ——
  - **孤儿卸载项**：控制面板里还有条目，但它的卸载程序文件已经不在了
  - **孤儿启动项 / 孤儿服务**：Run/RunOnce 与服务指向的可执行文件已不存在
    （实测能揪出卸载游戏后残留的反作弊驱动服务）
  - **失效快捷方式**：桌面 / 开始菜单里指向不存在目标的 `.lnk`
  - **疑似残留目录**：常见位置下不被任何已装程序认领的目录，按体积排序，
    标为**低置信、默认不勾选**（BCUninstaller 对同类结果同样列为 Questionable）
  识别「有主」用了多来源认领：`InstallLocation` + 卸载程序/图标目录 + MSI
  `Installer\Folders` 索引 + 所有服务的 ImagePath 目录 + 启动项 Exe 目录 ——
  只看 `InstallLocation` 会把 Logitech G HUB、SQL Server 这类程序误报成残留
  （实测误报从 111 个降到 45 个，且全部默认不勾选）
- **软件卸载逻辑重做**（参照 HiBit Uninstaller / Geek Uninstaller 的做法）：
  - 卸载命令行**按规则解析**（引号包裹 / 无引号含空格 / MSI 的 `{GUID}` / 环境变量），
    不再整条丢给 `cmd /c start` —— 原实现遇到 `C:\Program Files\...\unins000.exe`
    这类无引号路径会被空格截断，导致"卸载程序打不开"
  - MSI 统一改走 `msiexec /x {GUID} /qb /norestart`（不照搬原串，兼容 `/I` 形态）
  - 卸载程序文件已不存在时直接提示"疑似残留注册表项"，不再空转
  - **等卸载真正结束**（顶层进程退出 + 该程序的「已安装」注册表键消失，双判据）
    才进入残留扫描 —— 原实现命令一发就扫描，所以什么都扫不到
- **残留扫描范围大幅扩展**：
  - 安装目录**多来源推断**：`InstallLocation` + 注册表 `Inno Setup: App Path` /
    `App Path`（Inno、InstallShield 常写这两个值）+ 卸载程序所在目录
  - 目录扫描从"5 个根目录各一层"改为**两层递归**，补上最常见的
    `%LOCALAPPDATA%\Programs\<名>`、`Program Files\<厂商>\<名>`（原先全漏）
  - 新增检查位置：桌面与开始菜单**快捷方式**、**启动文件夹**、Recent 使用痕迹、
    LocalLow、**用户主目录点目录**（`.vscode` 这类配置/登录态）、WER 崩溃报告、
    MSI 安装目录索引 `Installer\Folders`、启动项、服务键、**事件日志源**
  - **登录数据也一起清**：Windows **凭据管理器**里的凭据（按程序名匹配 target，
    删除走 `CredDeleteW`）+ **计划任务**（`\Microsoft\...` 系统任务自动跳过）
- **新增「卸载前快照 → 卸载后复查」**：卸载前记下与程序相关的目录与注册表项，
  卸载后**仍存在**的项标记为「卸载前已有」并排在首位 —— 这是最确定的残留
- **误报控制**：滤掉 downloader / video / player 等品类通用词（避免命中无关程序）、
  编辑距离匹配加首字符守卫、低置信项在对话框里**默认不勾选**并标注「可能相关」
- **CPU 温度监控重做**：
  - 改为 **PDH 直读**（Windows 计数器 `Thermal Zone Information`，优先 1/10K 精度项），
    不再每次起 PowerShell 进程 —— 单次读取从 **1.4 秒降到 1 毫秒**，采样与刷新都能 1 秒同频
  - 多热区取**最高值**（最热区代表 CPU）；原实现取平均，会把主板/环境热区混进来把读数拉低
  - 新增**中位数(5) + EMA 滤波**：ACPI 读数在 1 秒内会 65↔72℃ 反复跳（实测跨度 8℃），
    滤波后稳定在 **±0.5℃** 内且不迟钝；真实负载突变（>15℃）立即跟随
  - PDH 不可用的机器自动回退原 CIM 路径（同样修正为取最高值）

**修复**

- **数据改成「打开读一遍，之后不再重读」**（本轮）。给每个页面加了一层**会话缓存**：
  数据在本次运行里只真正读一次，切页、切分类、排序、搜索一律复用首次读到的结果，
  不再反复去查系统；要让数据更新，只有两条路 —— 点右上角**刷新**，或者**刚做过一次
  写操作**（卸载、应用优化、启停服务等，这类必须重读才能显示正确状态）。实测把 12 个
  页面再走一遍，新起的子进程从 **24 个降到 2 个**（只剩 4 秒一次的 `nvidia-smi` 实时采样）。
  配套：网卡静态信息从「20 秒一查」改成**进程内只查一次**；CPU 页的进程列表、电源计划
  参数同样只在会话内读一遍（切回不重读）。**运行时长**改为本地推算 —— 数值照常走，
  但不再为了它去重读系统
- **老电脑「一打开就卡、CPU 被吃满」**（本轮修）。实测启动 2 秒内会并发拉起 **10 个
  PowerShell**，同时还有三个放大器：
  - **缓存击穿**：多个「带 TTL 缓存」的重查询**没有加锁**，1 秒心跳与两个常驻采样线程
    并发时同时看到缓存为空 → 同一条查询被重复发出（实测 `sys_basic` 跑 2 遍、`nvidia-smi`
    同一秒跑 2 遍）→ 全部加**单飞锁**
  - **失败无退避**：网卡信息查询只在成功时才写缓存，一旦查不到就变成「查不到 → 下一秒再查」
    的**每秒一个 PowerShell** 死循环 → 加 5 秒失败退避
  - **最小化后仍在轮询**：`QWidget.isVisible()` 在窗口最小化时**仍是 True**，程序收进任务栏
    后 1 秒心跳、`nvidia-smi`、PowerShell 全都没停 → 统一改用「页面可见 **且** 窗口未最小化」
  另外：子进程加并发闸门（同时最多 3 个，把启动那一波摊开）、主板/显示器/内存条三样 WMI
  查询**延后 2.5 秒**单独跑、`nvidia-smi` 采样 1.8s → **4s**、GPU 兜底 WMI 10s → **30s**、
  网络与温度采样线程**无人查看时自动降到 5 秒一次**。
  实测：`nvidia-smi` 每 2.1s → **每 4.2s**、网卡查询 每秒 1 次 → **每 20s**、`sys_basic` 2 次 → **1 次**

- **概览页「运行时长」读不出来**：`GetTickCount64` 返回的是 64 位毫秒数，但 ctypes 默认按
  **有符号 32 位**解析 —— 连续开机超过 **24.8 天**就翻成负数（实测 30 天 → -1702967 秒），
  界面自然显示不出来。已显式设置 `restype = c_ulonglong`，再加一层 WMI `LastBootUpTime`
  兜底 + `fmt_uptime` 空值保护（异常只影响这一个字段，不会带崩整张卡片）

- **启动权限：exe 一直以普通权限运行、写入类功能大半灰显**（本轮修）：打包脚本漏了 UAC
  声明，产物 manifest 写的是 `asInvoker` —— 双击**不弹 UAC**，程序按普通权限起，
  服务 / 注册表 / 策略 / 网络修复 / 软件卸载等按钮全部灰显。同时 `main()` 里有一处
  判定错误：`admin_mode = (mode == "admin")` **只看启动参数、不看实际有没有提权成功**，
  出现"假管理员"（按钮可点、操作全失败）；`relaunch_as_admin()` 也不检查
  `ShellExecuteW` 返回值，用户在 UAC 上点「否」会**静默退出**（观感就是"双击了打不开"）。
  现在：
  - 打包 manifest 直接声明 **`requireAdministrator`** —— 双击即由系统弹 UAC，进程从创建
    起就带管理员令牌，DNS / 服务 / 注册表 / 策略等写入功能全部可用
  - `admin_mode` 改为**一律以实际权限 `is_admin()` 为准**；提权失败时如实降级为普通模式
    （按钮灰显 + 明确提示），不再出现"假管理员"
  - `relaunch_as_admin()` 检查返回值：UAC 被拒时**不退出**、降级继续运行；并修正源码直跑
    时 `sys.executable` 的用法（原先会把 `python.exe` 当成目标程序）
  - 回归新增断言：打包产物的 manifest 必须是 `requireAdministrator`、不得回退 `asInvoker`
- **DNS 测速慢 / 长时间不出结果**（本轮修）：探测的**并行分支从未真正生效** ——
  组装任务列表时把 `(服务器, 分类)` 当成三元组拆包，每次都抛异常又被兜底 `except`
  静默吞掉，于是**悄悄退回串行**：114 台国内 DNS 要挨个等超时（实测 36.5 秒）。
  现已修正任务列表形态（统一三元组，并行与兜底共用），并把并发从 16 提到 32 ——
  实测 114 台 **36.5s → 18.6s**，并发峰值确认为 32；同时把这个「静默退化」的
  判别写进测试（并发峰值必须 > 1，否则判定失败）
- **「定位文件夹」定位不准 / 打不开目标位置**（本轮修）：
  - 原实现用 `explorer /select,<路径>` 的**参数数组**形式，路径含空格时
    （`C:\Program Files\...` 这类占大多数）Python 会给**整个参数补引号**，
    命令行变成 `explorer "/select,C:\Program Files\a b"`，explorer 解析失败 ——
    打开的不是目标位置。改为优先调用 Shell API `SHOpenFolderAndSelectItems`
    （直接吃 PIDL，没有命令行解析这一步），失败才退回字符串形式
    （`explorer /select,"<路径>"`，只给路径加引号）
  - Shell API 不认**正斜杠**路径（`SHParseDisplayName` 返回 `E_INVALIDARG`），
    统一先 `os.path.normpath` 规范化分隔符
  - 路径确实不存在时给出提示，而不是静默无反应
- **残留清理「扫得到、删不掉」**（本轮修）：
  - 注册表项删除时从**显示文本**反解 hive，而显示文本带 `[厂商键]` / `[卸载项]` 等标签前缀
    → 解析出的 hive 变成 `"[厂商键] HKCU"`，**所有注册表项一点删除就被判「超出安全范围」**。
    改为用单元格 `UserRole` 传递原始结构，显示与数据彻底分离
  - 删除安全闸原先只放行 `SOFTWARE\<一层>`：**产品键（两层）、卸载项（Uninstall 下）、
    启动项、服务**全部被拒。改为**按类别精确校验**（各自专属路径模式），
    越界项照旧拒绝（`SOFTWARE` 本身、`Uninstall` 键本身、盘根等不可删）
  - 启动项残留改为**只删自己那个值**（键是系统的），不再尝试删整个 Run 键
  - 文件删除白名单补齐**磁盘根直接子项**（原先 D 盘安装的程序扫得到但删不掉）+
    盘符大小写统一（`d:` 与 `D:\` 大小写不一致导致白名单永不命中）
- 温度读数跳变、刷新不及时（被 PowerShell 往返拖慢到 1.8 秒一次）
